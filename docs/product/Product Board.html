Promise + recurring developer check

Can a new app reach a trustworthy product-specific starting line without hidden setup?

01 · StartCopy a known source

Begin from a named commit or release, generate the project, and preserve the canonical source history.

Exit: reproducible checkout
02 · ConfigureName the real app

Replace bundle identity, API URLs, support/legal/App Store IDs, icon, product copy, and required entitlements.

Exit: no silent placeholder
03 · ReplaceBuild first value

Remove the example feature and connect onboarding, auth, data, and monetization only where the product needs them.

Exit: credible core promise
04 · ProveCross evidence gates

Compile first, then separately accept runtime, purchase, privacy, performance, accessibility, and physical-device behavior.

Exit: named evidence
05 · LearnFeed back the reusable part

Promote only repeated, product-neutral improvements into the canonical starter. Derived apps stay independent.

Exit: bounded upstream change

Trust controls must survive derivationSupport, legal, debug, data, subscription, recovery, and destructive actions require real product wiring.

Keep

Self-contained derived apps

Copy the reusable implementation. Do not create a runtime framework dependency that can break every shipped app at once.

Separate evidence

Compile is not quality

Source proves implementation; native preview or simulator proves inspected rendering; physical iPhone evidence proves device behavior and feel.

Never ship silently

Placeholders must stay visible

Sample identity, providers, URLs, icons, legal text, account deletion, and example features must be replaced or deliberately removed.

Now · Fix

Paid customers open immediately

Use the previously verified RevenueCat cache on the first frame and refresh without flashing the paywall.

Now · Safety

Unknown is not paid

Keep an unverified install gated and replace a slow or failed check with explicit Retry and Restore recovery.

Now · QA

Prove the full lifecycle

Trial, immediate unlock, relaunch, restore, offline cached access, and confirmed expiry must pass before rollout.
